**ricercar 0.10.1** keeps your place on plugin pages while music plays.

## Downloads

| Your system | File | Install |
|---|---|---|
| Debian 12+, Ubuntu 22.04+, Mint, Pop!_OS, Zorin, elementary | `ricercar_0.10.1-1_amd64.deb` / `_arm64.deb` | `sudo apt install ./ricercar_*.deb` |
| Fedora, openSUSE Tumbleweed / Leap 16, RHEL / Alma / Rocky 10+ | `ricercar-0.10.1-1.x86_64.rpm` / `.aarch64.rpm` | `sudo dnf install ./ricercar-*.rpm` (`zypper install` on openSUSE) |
| Arch, Manjaro, EndeavourOS, CachyOS, Omarchy | `ricercar-0.10.1-1-x86_64.pkg.tar.zst` | `sudo pacman -U ricercar-*.pkg.tar.zst` |
| Any distribution (portable) | `ricercar-0.10.1-x86_64.AppImage` / `-aarch64.AppImage` | `chmod +x ricercar-*.AppImage && ./ricercar-*.AppImage` |
| Any distribution (plain binaries) | `ricercar-0.10.1-linux-x86_64.tar.gz` / `-aarch64` | unpack, run `bin/ricercar` |

The packages need glibc 2.35 or newer. Verify a download with
[minisign](https://jedisct1.github.io/minisign/) and the project key:

```sh
minisign -Vm SHA256SUMS -P RWSLPLWZ/M4/9X1orGjyBkKYA7BmzgxxI8dveJ8YVcSQVrOpjinxS9fV
sha256sum --check --ignore-missing SHA256SUMS
```


## What's fixed

- **Pages keep their place while music plays.** Each new track no longer reloads the open page: plugin pages (a long playlist scrolled down) stayed put only until the next track, then jumped back to the top. Only the pages that show play counts and history (Home, an artist's top tracks, Tracks sorted by plays) update after a play.

> From 0.6.0 or later, *Update now* in Settings → About installs this version, checked against the signed `SHA256SUMS`.

**From source:** `cargo build --release` with Rust 1.92 or newer (see the README for per-distro dependencies).
