**ricercar 0.8.0** adds a fixed volume for bit-perfect listening and plays albums ripped as one file with a CUE sheet as their separate tracks, gapless.

## What's new

- **Fixed volume (bit-perfect).** Settings → Audio output → *Fixed volume* keeps the volume at 100 % and unmuted. Volume and mute changes are then ignored wherever they come from: the app's slider and shortcuts, phone apps over UPnP or OpenHome, media keys and MPRIS, `ricercar-cli`, plugins. Phone apps get a normal answer and see the volume stay at 100. Use your amplifier's volume. The signal path shows *Volume fixed at 100 %*.
- **CUE sheets.** An album ripped as one audio file (FLAC, WAV, AIFF, ALAC) with a `.cue` sheet now shows as its separate tracks, with titles, numbers and durations from the sheet.
  - Each track plays exactly its part of the file.
  - Consecutive tracks are gapless to the sample, so live albums flow as recorded.
  - Seeking, position and duration are relative to the track.
  - Favourites, play counts, playlists, scrobbling and search work as for any track; the media server shares the tracks too.
  - Sheets in UTF-8 or Windows encodings, several files per sheet and pregaps are handled.
- **Outputs that are not connected.** When the output you picked is gone (a Bluetooth speaker that is off), ricercar shows its name with *(not connected)*. The signal path names what really plays: PipeWire's default output.
- **Readable network errors.** An error from ListenBrainz, Last.fm, radio or lyrics services reads like *HTTP 502 Bad Gateway* instead of showing the server's whole page.
- **Fixes.** Long text, a token or a path, stays inside its field instead of covering the button next to it.

> This version updates the library database. Going back to 0.7 afterwards is not supported: it does not understand the tracks of CUE sheets.

> From 0.6.0 or later, *Update now* in Settings → About installs this version, checked against the signed `SHA256SUMS`.

## For plugin authors

- `player.set_volume` and `player.set_mute` are ignored while the user has fixed the volume; the next `player.state` reports 100.

**From source:** `cargo build --release` with Rust 1.92 or newer (see the README for per-distro dependencies).
